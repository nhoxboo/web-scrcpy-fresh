# Web Scrcpy Fresh

Remote Android screen-control web app (scrcpy over WebSocket).

## Run
```bash
SCRCPY_LOCAL_PORT=5555 ADB_SERIAL=192.168.1.108:5555 "/c/Program Files/Python312/python.exe" app.py --port 8000
```
- Port: **8000**
- Login: `admin` / `Admin@2026`
- Uses **eventlet** — do NOT use gunicorn (broken on Windows).
- Use `terminal(background=true, notify_on_complete=true)` to launch, never `nohup`/`&`.
- Scheduled task: `Hermes_scrcpy` (auto-restarts this on boot/logon — check it before manually re-launching to avoid port conflicts).

## Network notes
- VPN SoftEther remapped port 5555→6666 previously, then scrcpy was moved back to 5555. If ADB/scrcpy connection fails, check for port collision with SoftEther first.
- socket.io / WebSocket: router NAT blocks WAN WebSocket, so `transports=['polling']` is required server-side for external access. Don't "fix" this back to websocket-only — it was intentional to work around the router.
- Known outstanding gaps: stale session cleanup logic exists but may need re-verification; `facebook-wda` + `tidevice` are needed for iOS support (not yet installed).

Always use `/c/Program Files/Python312/python.exe` explicitly — the `hermes` venv is Python 3.11 and lacks Flask/eventlet needed by this app.
